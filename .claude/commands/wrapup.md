---
description: 作業完了時の締め処理を行う（タスク消し込み・課題の反映・品質チェック報告）
---

作業単位を完了させる。`work/` の該当ディレクトリを対象に、以下を順に実行する。
**途中で問題が見つかったら止めて報告する。完了していないものを完了と報告しない。**

## 1. 品質チェック

`docs/architecture.md` に記載のコマンドを実行する（存在するもののみ）。

- テスト
- 型チェック
- lint / formatter

**エラーが残っている場合はここで止める。** 修正するか、
直せない理由を説明して判断を仰ぐ。勝手に「完了」に進まない。

## 2. 受け入れ条件の確認

`1_requirements.md` の受け入れ条件を1つずつ確認し、`- [x]` に更新する。

満たせなかった条件があれば、その理由とともに報告する。
「だいたいできた」で通さない。

## 3. タスクの消し込み

`3_tasks.md` のすべてのタスクを `- [x]` に更新する。

未完了のタスクが残っている場合：
- 今回やるべきものなら → 作業を続ける（締め処理はまだ早い）
- スコープ外と判断したものなら → `docs/backlog.md` に移し、理由を添える

## 4. 課題の棚卸し

今回の作業中に見つけたものを整理する。

| 見つけたもの | 送り先 |
|--------------|--------|
| 不具合（直していないもの） | `docs/known-issues.md` 種別=バグ |
| 気になるコード（動くが汚い・遅い） | `docs/known-issues.md` 種別=負債 |
| 機能のアイデア・やりたいこと | `docs/backlog.md` |
| 今回解決した既存の課題 | `known-issues.md` の「なおした日」を記入 |

追記は承認不要。ただし**何を追記したかは必ず報告する**。

## 5. `3_tasks.md` の削除

すべて完了したら `3_tasks.md` を削除する。
`1_requirements.md` と `2_design.md` は仕様の記録として残す。

## 6. docs/ への反映を提案

以下に該当するものがあれば、**内容を報告して承認を得てから**更新する。
承認なしに `docs/` を書き換えない（`backlog.md` と `known-issues.md` は除く）。

- 技術スタックや構造を変えた → `docs/architecture.md`
- 重要な技術判断をした → `docs/decisions/` に ADR を追加
- コード規約を決めた・変えた → `docs/conventions.md`
- 起動方法・セットアップ手順が変わった → `README.md`
- プロダクトの方向性に関わる決定をした → `docs/concept.md`（要相談）

## 7. 完了報告

以下の形式でまとめる。

```
## 完了報告：<作業タイトル>

### やったこと
- 

### 品質チェック
- テスト: <結果>
- 型チェック: <結果>
- lint: <結果>

### 積み残し
- backlog.md に追加: 
- known-issues.md に追加: 

### docs/ への反映（要承認）
- 
```

## 8. コミットの確認

**コミットはユーザーから指示があったときのみ行う。**
締め処理の最後に「コミットしますか？」と確認する。勝手にコミットしない。
