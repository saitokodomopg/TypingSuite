# Concept

何を・誰のために作るか。**変更には承認が必要。**

プロダクトの方向性を変える変更は、新規ファイルで議論・合意してから反映する。

---

## 一言でいうと

タイピングの「練習」「記録」「検定」をひとつにまとめた、
プログラミング教室のための Web アプリ。

生徒は自分の上達が見え、先生はクラス全員の進み具合が見える。

---

## 想定ユーザー

| 誰 | 人数の目安 | どう使うか |
|----|-----------|------------|
| 教室の生徒（小学生・中学生が中心） | 約50名 | 練習モードでタイピングを練習し、自分の記録の伸びを見る |
| 先生（コーディネータ） | 数名 | 管理機能でクラス全員の記録を見る。検定を実施して級を認定する |

開発するのは教室の生徒 3〜5 名。
ただし**使うのは教室の全生徒（約50名）**であり、作る人とは別。

このため「作った本人だけがわかる作り」では通用しない。
説明なしで使えること、記録が失われないことが、身内ツール以上に強く求められる。

**保護者はこのアプリを使わない。**
成果は先生からのレポート・報告・賞状として伝わる。
直接のユーザーではないが、**成果の受け手**として想定しておく。

---

## 解決したい困りごと

| 困りごと | このアプリでどうなるか |
|----------|------------------------|
| タイピング練習が単調で続かない | 複数の練習モードとゲーム要素で飽きにくくする |
| 上達しているのか自分でわからない | 記録を残し、推移をグラフで見せる |
| 先生が50名ひとりひとりの進み具合を把握できない | 全員の記録をサーバーに集約し、管理機能で一覧できるようにする |
| 練習が止まっている生徒に気づけない | 一定期間記録のない生徒を先生に知らせる |
| 「どのくらい打てる」が客観的に言えない | 検定機能で級を認定し、達成を形にする |

---

## 機能の柱

### 1. 記録機能

練習・検定の結果を保存し、振り返れるようにする。

- 1回ごとの結果（速度・正確さ・かかった時間・ミスしたキー）
- 推移のグラフ
- 全生徒分をサーバーに集約し、先生が見られる

**記録は自動で保存される。** 生徒が「保存する」を押す必要はない。
打ち終わればその場で記録される。

このため**先生が記録を訂正する機能は作らない。**
手で入力したものではないので、間違いが入り込む余地がないため。

**記録は消さずに残し続ける。** 卒業した生徒の分も含めて残す。
1回の結果は小さく、50名が何年使っても負担にならない見込みのため。

### 2. 練習機能

練習は大きく **2つのモード** に分かれる。

| モード | 内容 |
|--------|------|
| シンプル | 表示された課題をただ打つ。余計な要素なし |
| ゲーム | スコア・制限時間・演出などで楽しく打つ |

シンプルモードは、**課題の種類**を切り替えて使う。

| 課題の種類 | 内容 |
|------------|------|
| タッチタイプ | 指の定位置を覚える。キーを限定して練習 |
| 英単語 | 英単語を打つ |
| ローマ字 | 日本語をローマ字入力で打つ |

**ゲームモードはアイディア次第で増やしていく。**
今は中身を決めきらず、後から足せる形にしておく。

課題の種類とゲームは、どちらも**増えることを前提**にする。
土台を作り直さずに足せるようにしておく。

### 3. 検定機能

決められた課題・制限時間で実施し、基準を満たせば級を認定する。

検定には **2つの受け方** がある。

| 受け方 | いつ | 問題 | 級の認定 | 記録 |
|--------|------|------|----------|------|
| 自由受験 | 生徒が好きなときに | 毎回ランダム | **されない** | 残る |
| 正式検定 | 先生が決めた日時に集合して一斉に | その回に1問を抽選し、受験者全員が同じ問題 | される | 残る |

- 級ごとの合格基準（速度・正確さ）
- 合否の判定と認定の記録
- **級の基準は既存の検定を参考にする**（独自基準を一から作らない）

既存検定を参考にする理由：基準に納得感が生まれ、
「外でも通用する力がついた」と生徒・保護者に説明できるため。
どの検定を参考にするかは別途調査して決める。

**自由受験で合格ラインを超えても級はつかない。**
理由：級は「同じ条件で受けた」ことに裏打ちされて初めて意味を持つため。
自由受験は本番前の力試しであり、記録は残るので伸びは追える。

**正式検定は「回」という単位を持つ。**
先生が回を作り、その回に問題を1つ抽選して、受験者全員に同じ問題を出す。
全員が同じ条件で受けるため、合否を並べて比べられる。

### 4. 管理機能（先生用）

50名規模の運用を支える。生徒には見えない領域。

| 機能 | 内容 |
|------|------|
| 生徒名簿の管理 | 生徒の登録・クラス分け・卒業した生徒の非表示 |
| クラス全体の記録閲覧 | 全員の最新記録・練習回数を一覧表示。並べ替えできる |
| 個人の詳細確認 | ひとりを選んで推移グラフ・ミスの傾向を見る |
| 練習していない生徒の把握 | 一定期間記録のない生徒を目立たせる |
| 検定の実施と認定 | 正式検定の回を作り、合否を確認して級を認定する |
| 課題文の管理 | 練習で使う文章を追加・編集する |
| 個人レポートの出力 | 生徒ひとり分の推移・級・練習回数をまとめる（保護者への報告用） |
| データのエクスポート | CSV / JSON で書き出す（面談資料・バックアップ用） |

**「練習していない生徒の把握」を重視する。**
記録を集める目的は、上位者を褒めること以上に、
止まっている生徒に気づいて声をかけられるようにすることにあるため。

**保護者はアプリを使わない。**
保護者が知るのは、先生から渡されるレポート・報告・賞状を通じてになる。
このため個人レポートは、**アプリを知らない人が読んでわかる**必要がある。

## 主要な画面の流れ

### 生徒

```
ホーム
 ├─ 練習をはじめる
 │    ├─ シンプル → 課題の種類を選ぶ ─┐
 │    │   （タッチタイプ / 英単語 / ローマ字）
 │    │                                ├→ 練習画面 → 結果画面 ─┐
 │    └─ ゲーム → ゲームを選ぶ ────────┘                        │
 │                                                               │
 ├─ 記録を見る ←────────────────────────────────────────────────┘
 │    （推移のグラフ・過去の結果一覧）
 │
 └─ 検定を受ける
      ├─ 自由受験 → 検定画面 → 結果（級はつかない）
      └─ 正式検定 → 先生が開いた回に参加 → 検定画面 → 合否
```

### 先生

```
管理ホーム
 ├─ 生徒一覧（記録・練習回数・止まっている生徒の強調）
 │    ├─ 個人詳細（推移・ミスの傾向）
 │    └─ 個人レポート出力
 ├─ 正式検定
 │    ├─ 回を作る（日時・級・問題の抽選）
 │    └─ 合否の確認と級の認定
 ├─ 課題文の管理
 └─ エクスポート
```

## 「これができたら成功」と言える条件

1. 生徒が1回の練習で終わらず、続けて2回以上打っている（記録から確認できる）
2. 生徒が自分の1か月分の推移を、1画面で見比べられる
3. 先生が50名の状況を一覧で確認でき、止まっている生徒に気づける
4. 先生が個人レポートを出して、保護者に成果を説明できる
5. 開発した生徒が「自分が作った部分」を指して説明できる

## 大事にすること

### 使う側

- **迷わない** — 小学生が説明なしで練習を始められる。
  作った生徒が横にいなくても使えること
- **正しく打てたと感じる** — ローマ字は複数の打ち方を許容する。
  「し」は `si` でも `shi` でも正解にする。本物のタイピングソフトと同じ体験にする
- **記録が消えない** — 練習した事実が失われると、続ける気持ちが折れる。
  サーバーに保存された記録は、端末を変えても消えない

### 動く前提

**このアプリはオンラインで使う。**

記録はサーバーに保存し、端末には残さない。
生徒が別の端末で開いても、自分の記録は続けて見られる。

通信が切れた場合、その回の練習・検定は中断し、記録されない。
理由：端末に一時保存する仕組みを持たないぶん作りが単純になり、
「サーバーにあるものがすべて」と言い切れるため。

教室はネットにつながっている前提で運用する。

**生徒は先生が配る ID とあいことば（4桁の数字）で入る。**

生徒はメールアドレスを持っていないため、メールを使わずに入れるようにする。
あいことばを忘れても、先生が管理画面からその場で配り直せる。

「自分の記録」が続いていくことを支えるために、誰が打ったかは必ず記録に結びつける。
一方で、小学生が覚えられない仕組みにはしない。
守っているのは教室内の練習記録であり、厳重さより続けられることを優先する。

先生は全生徒の記録を扱うため、生徒とは別にメールアドレスとパスワードで入る。

### 作る側

- **土台を先に作る** — 打鍵の判定・課題の受け渡し・結果の返し方は共通の土台に置く。
  土台ができてから、課題の種類とゲームを分担する。
  土台の前に分担すると、同じものを別々の書き方で作ってしまう
- **分担しやすい** — 課題の種類やゲームは1人1つで担当でき、他人のファイルを触らずに済む
- **後から足せる** — 課題やゲームを増やすのに土台を作り直さなくてよい
- **途中参加できる** — 後から入った生徒もすぐ手をつけられる
