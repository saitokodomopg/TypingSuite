# 1. Requirements — 疎通確認（練習画面の縦切り）

## 目的

「土台構築」work で `src/core/` の判定エンジン・型・registry を実装したが、
ユニットテストのみで確認しており、**実際に画面からキーを打って一連の流れが動くこと**は
まだ誰も確認していない。

課題の種類（`tasks/`）を分担する前に、`core/` のインターフェースが実際に画面から
使いやすい形になっているかを最小構成で検証する。ここで使いにくさが見つかれば、
分担前に `core/` 側を直せる。

## やること

- `src/tasks/touch-type/` にダミーの課題を1つ実装し、registry に登録する
  （中身は最小限。本格的な課題コンテンツは分担後に別途作る）
- `src/features/practice/` に最小限の練習画面を1つ実装する
  - 課題文の表示
  - キー入力 → `core/engine` の判定（継続/確定/ミス）→ 見た目への反映
  - 全ユニット消化後、`core/engine/score` の結果（速度・正確さ・ミス）を画面に表示する
- 上記を `npm run dev` で実際に手打ちして動作確認する

## 受け入れ条件

- [ ] ブラウザで練習画面を開き、キーボードで課題文を最後まで打ち切れる
- [ ] ミスキーを打ったときにミスとして扱われ、バッファが進まないことが画面上で確認できる
- [ ] 打ち終わったあとに速度・正確さ・ミスしたキーが画面に表示される
- [ ] `npm run test` / `npm run typecheck` / `npm run lint` がすべて通る
- [ ] `core/` のインターフェースを変更した場合、変更内容と理由を報告する
      （変更しなかった場合はその旨を報告する）

## やらないこと（スコープ外）

- Supabase への保存・認証（`lib/`）— 別workで対応
- 本格的な課題コンテンツ・複数の課題の種類 — 分担後に対応
- 画面デザイン・スタイリングの作り込み — 動作確認が目的のため最小限でよい
- ゲームモード
