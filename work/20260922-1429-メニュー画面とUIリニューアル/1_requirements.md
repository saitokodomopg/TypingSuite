# 1. Requirements — メニュー画面追加とUIリニューアル（案B）

## 背景

生徒が `src/tasks/` に課題（タイピングアプリのバリエーション）を追加していく前提
（`docs/architecture.md` 拡張の仕組み）に対し、現状は `PracticeScreen` 1画面に
課題切り替えボタンが並ぶだけで、以下が不便だった。

- 課題が増えるほど1画面内のボタンが増えて煩雑になる
- 個別の課題だけを直リンクで開いて単体動作確認する手段がない

あわせて、直近提示したUI比較モックアップのうち「案B（UIライブラリ／コンポーネント
強化）」の見た目を採用し、練習画面の視認性を上げる。

## やること

### 1. ルーティング導入

- `docs/architecture.md` で採用済みの React Router を実際に導入する（新規の技術決定ではない）
- ルート構成：
  - `/` … メニュー画面（新規）
  - `/practice/:taskId` … 練習画面（既存 `PracticeScreen` をURLパラメータ対応に変更）

### 2. メニュー画面（新規）

- `src/features/menu/` に新規作成
- `core/registry` に登録されている課題を一覧カード表示する
- カードをクリックすると `/practice/:taskId` に遷移する
- 課題が増えてもコード変更なしで一覧に反映される（registry経由のため）

### 3. 練習画面のルーティング対応

- `taskId` をURLパラメータから取得するように変更する
- `/practice/:taskId` に直接アクセスした場合も、その課題単体で正しく開けるようにする
  （生徒が自分の担当課題だけを直リンクで動作確認できるようにするため）
- 存在しない `taskId` の場合は「課題が見つかりません」等の表示のままにする
- 画面内の課題切り替えボタンは、クリックで対象のURL（`/practice/:taskId`）に
  遷移する形に変更する（他の課題への切り替え導線は維持する）

### 4. UIリニューアル（案Bの見た目を適用）

対象：メニュー画面・練習画面の両方

- 参考：会話中で提示したモックアップ（UIライブラリ導入案）
- **新規の外部UIライブラリ・アイコンライブラリは追加しない。** モックアップと同様、
  自前CSS＋インラインSVGアイコンで実現する（`docs/architecture.md` の依存を
  増やさない方針に合わせる）
- 反映する要素の例：カード化、入力文字の色分け（入力済み／次の1文字を強調）、
  進捗のリング表示、課題選択のピル型ボタン、結果画面のアイコン付き表示 など
- フォントは Google Fonts を利用する想定（見出し用・等幅の入力表示用）

### 5. 既知課題の解消（known-issues.md No.1、あわせて対応）

- `src/tasks/touch-type-dk/` （複数課題登録の動作確認用ダミー課題）を削除する
- 実課題が2件（`touch-type` / `home-position-basic`）揃ったため、
  `docs/known-issues.md` の削除条件を満たしている
- メニュー画面をつくるとダミー課題も一覧に並んで目立ってしまうため、今回あわせて削除する
- 対応：`src/tasks/touch-type-dk/` を削除し、`src/tasks/index.ts` の登録行を削除し、
  `docs/known-issues.md` No.1 の「なおした日」を記入する

## やらないこと（スコープ外）

- ゲーム（`games/`）のメニュー対応（`Game` 型が未整備のため。`concept.md` の
  「まだ決めていないこと」参照。型が整ったら別作業で対応）
- 記録・検定など他の `features/`（`records/` `exam/` `admin/`）の新規実装
- Supabase連携（記録の保存・取得など）
- スマホ・タブレット対応（`architecture.md` によりPC専用のため）
- 課題選択の重複防止の仕組み化（`docs/backlog.md` に別項目としてあるため今回は対象外）

## 受け入れ条件

- [ ] `/` にアクセスするとメニュー画面が表示され、登録されている全課題がカードで一覧表示される
- [ ] メニューの課題カードをクリックすると `/practice/:taskId` に遷移し、対象課題の練習画面が開く
- [ ] `/practice/:taskId` に直接アクセスしても、その課題単体で練習画面が開く（メニュー経由不要）
- [ ] 存在しない `taskId` へアクセスした場合、クラッシュせず「課題が見つかりません」等の表示になる
- [ ] 練習画面内の課題切り替えボタンから、他の課題のURLへ正しく遷移する
- [ ] メニュー画面・練習画面のUIが「案B」の見た目（カード・色分け・進捗表示・アイコン等）になっている
- [ ] 既存の打鍵判定・結果表示・リトライ機能が壊れていない
- [ ] `src/tasks/touch-type-dk/` が削除され、`docs/known-issues.md` No.1 の「なおした日」が記入されている
- [ ] `npm run test` / `npm run typecheck` / `npm run lint` がすべてエラーなしで通る
- [ ] `npm run dev` でブラウザから動作確認する（メニュー→練習画面の遷移、直リンクアクセス、UI見た目の3点）
- [ ] wrapup後、PRで `main` にマージし、本番URLで動作確認する
