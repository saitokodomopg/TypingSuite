# 1. Requirements — 練習画面UI改善3点

## 目的

`home-position-basic` 実装時のブラウザ確認で見つかった、練習画面（`PracticeScreen`）の
使いにくさを解消する。`docs/backlog.md` に積んであった3点をまとめて対応する。

## やること

- 課題の選択をセレクトボックスからボタン（課題ごとに1個）に変更する
- 入力欄で「入力済みの文字」と「これから打つ文字」を色で区別する
  （これから打つ文字を薄い色にする）
- 練習エリアに「リトライ」ボタンを追加し、同じ課題を最初からやり直せるようにする

## 受け入れ条件

- [x] 課題一覧がボタンで表示され、クリックした課題に切り替わる
      （セレクトボックス・`<select>` は使わない）
- [x] 入力欄で「入力済みの文字」と「これから打つ文字」が見た目で区別できる
      （これから打つ文字をグレーで表示。ユーザーの指示により、さらにその先の未入力文字は表示しない仕様に変更）
- [x] リトライボタンが表示され、押すと同じ課題が最初からやり直せる
      （入力途中・結果表示中のどちらから押しても、進捗と結果表示がリセットされる）
- [x] `npm run test` / `npm run typecheck` / `npm run lint` がすべてエラーなしで通る
- [x] `npm run dev` でブラウザから動作確認する（ユーザーが確認済み）
- [ ] `wrapup` 後、このブランチを PR で `main` にマージする
- [ ] `main` への反映後、Cloudflare Pages への自動デプロイが完了し、本番URLで動作確認する
      （`main` への push で自動デプロイされる。手動デプロイ操作はしない）

## やらないこと（スコープ外）

- デザインの作り込み（配色の微調整・アニメーションなど）はしない。区別がつく最低限の見た目にとどめる
- ボタンの並び順・グルーピング（カテゴリ分けなど）は変更しない。現在のリスト順のまま
- リトライ時に統計（過去の記録）を保存する機能は作らない。今回はやり直しの導線のみ
